**(1) `it.summaryModel === 'failed'` 분기를 if문 최상단에 추가.** 이 분기는 다음 구조의 HTML 반환:

```
return `
  <div style="padding:${topPad} 0 22px;${topBorder}">
    ${metaLine ? `<div style="margin-bottom:8px;">${metaLine}</div>` : ''}
    <div style="font-family:${FONT_SERIF};font-size:20px;font-weight:500;line-height:1.3;margin:0 0 10px;letter-spacing:-0.005em;">
      <a href="${escapeAttr(it.url)}" style="color:${COLOR.link};text-decoration:underline;text-decoration-color:${COLOR.linkUnder};">${escapeHtml(it.title)}</a>
    </div>
    <div style="font-family:${FONT_MONO};font-size:11px;letter-spacing:0.12em;color:${COLOR.muted};text-transform:uppercase;margin:0 0 12px;">⚠ 요약 일시 불가</div>
    <a href="${escapeAttr(it.url)}" style="display:inline-block;font-family:${FONT_MONO};font-size:10.5px;letter-spacing:0.08em;color:${COLOR.link};text-transform:uppercase;text-decoration:none;border-bottom:1px solid ${COLOR.linkUnder};padding:8px 0 7px;">원문 읽기 &nbsp;→</a>
  </div>`;
```

핵심: (a) 본문 `<p>` 라인이 출력에 포함되지 않는다 (title-as-summary_ko 중복 제거), (b) `it.summaryError`가 함수 내 어디에서도 참조되지 않는다, (c) `⚠ 요약 일시 불가`는 monospace muted-gray 톤으로 기존 meta-line과 동일 weight.

`topPad` / `topBorder` / `metaLine` / `published` / `meta` 등 helper 변수는 함수 시작부에 그대로 계산하되, 'failed' 분기에서는 `badge`/`summaryText` 변수는 사용되지 않으므로 'failed' 분기가 그 변수 계산보다 위에 배치되도록 한다 (또는 그 변수들을 'failed'가 아닐 때만 계산하도록 한다 — 어느 쪽이든 'failed' 분기에서 summaryError 참조가 없어야 한다).

**(2) 기존 `badge` ternary에서 'failed' 처리 라인 제거.** 현재 line 177-178 `: it.summaryModel === 'failed' ? \` <span ... >⚠ 요약 실패${it.summaryError ? ...}\`</span>` 분기는 'failed'가 더 이상 이 ternary에 도달하지 않으므로 완전히 삭제. 변경 후 badge 정의는 다음 형태:

```
const badge =
  it.summaryModel === 'skipped'
    ? ` <span style="font-family:${FONT_MONO};color:${COLOR.warnBorder};font-size:11px;letter-spacing:0.04em;">⚠ 본문 없음</span>`
    : '';
```

(즉 'failed' ternary arm 1개 제거, 'skipped' arm 유지, default empty string.)

**(3) 'ok' / 'skipped' 분기는 기존 동작 그대로.** 본문 `<p>` line, badge 추가, 정상 summary_ko 렌더 모두 유지. 'failed'가 아닐 때 'skipped' badge 동작에 영향 없음.

**(4) `summaryText`/`summary_ko ?? it.title` 폴백 로직은 'ok'/'skipped' 분기에서만 사용.** 'failed' 분기에서는 summaryText를 출력하지 않으므로 fallback `?? it.title` 자체가 더 이상 title 중복의 원인이 되지 않는다 (이중 안전: 폴백은 남기되 폴백이 출력되는 경로 자체가 사라짐).

**금지:**
- `renderDemotedBlock()` 함수 본체나 시그니처를 수정하지 않는다 (D-01).
- 기존 design token(`COLOR`, `FONT_MONO`, `FONT_SERIF`, `FONT_SANS`)에 새 항목을 추가하지 않는다 — 기존 것만 사용.
