## Blockers

### BLOCKER-1: DQOBS-01 weekly observability regression — ✓ RESOLVED

**Resolved:** 2026-05-23 via quick task `260523-mtz`, commit `04a572e`
**Applied fix:** Option B from the original sketch — `isEmptyFirm` predicate widened from two-signal to four-signal. A row is empty only when `fetched===0 AND bodyLengths.length===0 AND guardCount===0 AND confidence(H+M+L)===0`. Daily-style empty firms still render as em-dash (no regression — 22 prior tests stay green); weekly firms with cluster/low-conf results now render their actual counts. Test added at `test/observability/recorder.test.ts` mirroring the runWeekly write pattern. 23/23 tests pass.
**Side-effect resolution:** DQOBS-02 partial-status removed — the marker visibility was always intact; the per-firm H/M/L cross-check is now visible via the same fix.

## Tech Debt (non-blocking)

### TD-1: settings.yaml ↔ daily.yml sync drift

`scripts/sync-schedule.ts:24` rewrites only `daily.yml` from `config/settings.yaml`. After Phase 13 split there are two crons (daily + weekly) but only one source-of-truth. Running `pnpm sync-schedule` today silently overwrites the split. Either:

- Extend sync-schedule to know about both files
- Delete sync-schedule and document cron edits as direct yml changes
- Add a guard that fails sync-schedule if split is detected
